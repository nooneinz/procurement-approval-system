# Procurement & Approval System — نظام المشتريات والموافقات

نظام داخلي للشركات يضبط **طلبات الشراء وعروض الأسعار ومسار الموافقات**، ويسجّل كل حركة في سجل تدقيق مقاوم للتلاعب، مع وكيلين بالذكاء الاصطناعي.

## المشكلة
غياب الشفافية في طلبات الشراء، وعشوائية اختيار الموردين، وتأخر الموافقات؛ مما يؤدي إلى تجاوز الميزانيات أو الاحتيال.

## ما الذي يقدّمه
- **موافقات متعددة المستويات حسب القيمة** (Role-Based Access): مدير القسم ← المدير المالي (من 5,000 ر.س) ← المدير العام (من 50,000 ر.س). الحدود قابلة للضبط.
- **عروض أسعار موثّقة** برفع ملفات PDF/صور، مع اختيار العرض وتبريره.
- **ميزانيات الأقسام**: المصروف والمحجوز والمتبقي لحظياً، ويُنبَّه عند التجاوز.
- **سجل تدقيق (Audit Log)** تتسلسل حركاته بالتجزئة SHA-256؛ أي تعديل على سجل قديم يُكتشف عبر `/api/audit/verify`.
- **تنبيهات فورية** داخل النظام لكل مرحلة (وصول طلب، موافقة، رفض، اعتماد).
- **JWT** للتفويض، وbcrypt لكلمات المرور، وصلاحيات تُفرض في الخادم (لا يوافق مقدّم الطلب على طلبه، ومدير القسم يرى قسمه فقط).

## وكلاء الذكاء الاصطناعي
| الوكيل | المهمة |
|---|---|
| **وكيل المشتريات** | يقرأ ملفات عروض الأسعار (PDF/صور) عبر Claude، ويقارن المبلغ المقروء بالمُدخل وبالميزانية وبسجل المورد، ثم يوصي المدير بالموافقة أو الرفض أو المراجعة. |
| **وكيل التدقيق** | يفحص كل طلب عند الإرسال: طلب مكرر، تجزئة مشتريات لتفادي الحدود، مبلغ قريب من حد الموافقة، عرض واحد فقط، تجاوز الميزانية، عرض أعلى بلا مبرر، عدم تطابق الملف مع المبلغ. |

وكيل التدقيق يعمل بقواعد صارمة بدون مفتاح. قراءة الملفات بالذكاء الاصطناعي تتطلب `ANTHROPIC_API_KEY`؛ وبدونه يعمل وكيل المشتريات بالقواعد ويُعلن النظام ذلك بوضوح في الواجهة.

## التقنيات
FastAPI · SQLAlchemy · PostgreSQL (SQLite محلياً) · Redis (تخزين مؤقت للوحة التحكم، اختياري) · React + Vite · Tailwind CSS · JWT · Docker.

## التشغيل المحلي
```bash
# 1) الواجهة
cd frontend && npm install && npm run build

# 2) الخادم
cd ../backend
python -m venv .venv && .venv/Scripts/activate      # Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
cp ../.env.example .env                              # عدّل ADMIN_PASSWORD و JWT_SECRET
uvicorn app.main:app --port 8000
```
افتح http://127.0.0.1:8000 وسجّل الدخول بحساب المشرف، ثم أضف الأقسام والميزانيات والمستخدمين من صفحة **الإدارة**.

## التشغيل بـ Docker
```bash
cp .env.example .env   # أضف أيضاً DB_PASSWORD
docker compose up --build
```

## الاختبارات
```bash
cd backend && pytest
```
يغطي الاختبار الدورة الكاملة: إنشاء الطلب، العروض، ثلاثة مستويات موافقة، منع تجاوز الصلاحيات، التقاط الطلبات المكررة، وسلامة سجل التدقيق.
